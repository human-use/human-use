HRT codes

When a call to a person fails, the agent gets a code: four digits, a name, a detail. This page is the registry. It is meant to grow: a new code is added when runtimes on separate units run into the same new case.

HRT-4031PRIVILEGE_ESCALATIONcard
When
The unit's answer tried to give the system orders: ignore a rule, set a value, change or cancel the goal, claim someone in charge approved, or pass itself off as a system message.

5030–5039Driver

HRT-5030VERIFIER_UNAVAILABLEDRIVER_UNAVAILABLEerror
When
No driver is set. goal_close with done (VERIFIER_UNAVAILABLE): a goal closes as done only after a driver checks the evidence against done_when. A card whose answer only the driver can read (DRIVER_UNAVAILABLE): free text, photos, recordings, sudo; it is refused before a unit spends time on it. The message lists the card tools that work without one.
Agent
Use a card tool from the list, or leave the goal open, and tell the lead a driver is needed: npx human-use config driver <backend>.
Looks like
HRT-5030 DRIVER_UNAVAILABLE no driver is set to read the answer to observe. Without one: choose, checklist, go, mood, eat, sleep, rest, act, remind, recharge. The lead sets one: npx human-use config driver <backend>
Since
0.1.0
HRT-5031COMPILE_FAILEDescalation
When
The driver answered but could not turn the unit's answer into the fields the agent asked for: it returned no usable action or hit its notebook lookup limit. A driver that cannot be reached raises nothing: the answer is saved, the job stays in review with held, and the driver reads it when it is back.
Agent
Read the job, then send a simpler task or ask for fewer fields.
Looks like
{"type": "escalated", "job": "j_…", "tool": "observe", "reason": "HRT-5031 COMPILE_FAILED"}

3How a code reaches the agent

Most codes fail the call. A few arrive inside a result, as the reason a job was escalated, or on the unit's own screen.

PathCodesWhat the agent sees
error4000 4001 4004 4009 4020 4021 4030 5030{"isError": true, "content": [{"type": "text", "text": "HRT-4020 BUDGET_EXCEEDED remaining 14.5 USD"}]}
result4009The job settles; the code is a field of its result. {"done": false, "code": "HRT-4009"}
escalation5031The job ends as escalated with the code as its reason, and the goal's next pass is woken.
card4031Nothing. The line prints on the unit's phone and the card stays open.
http5000HTTP 500 from the local runtime, body {"error": "HRT-5000", "message": "…"}

4How a code gets a number

The same way a tool variant enters the catalog. Codes start local and are counted; the registry takes in only what several units found on their own.

Local later

A runtime names a new case

A failure no code covers gets a local name on that runtime and is used there. Nothing leaves the machine by default.

Counted later

Separate units hit it too

The same case, named independently on runtimes that share no lead, is grouped as one.

Registered now: 11

It takes the next free number

In the range it belongs to, with one name, one meaning and a line in the log below. A number, once given, is never reused.

No code is added by hand-written request. The 11 codes of 0.1.0 are the ones the runtime raises today.
