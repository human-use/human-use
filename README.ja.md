# Human Use

人間用のデバイスドライバ。

Human Use は人を MCP ツールとして AI エージェントにつなぎます。エージェントが `photo`、`errand`、`patch`、`eat` を呼ぶと、その人のスマートフォンにカードが表示され、結果が JSON で返ってきます。

何もインストールせずに試すには、[humanuse.dev](https://humanuse.dev) を開いてスマートフォンでコードを読み取ります。スマートフォンにカードが 3 枚表示され、それぞれの回答はエージェントが受け取る JSON としてページに戻ってきます。

ステータス：プレリリース。runtime、MCP ツール、スマートフォンのページは実装済みです。driver は Claude、Codex、Ollama、OpenAI 互換のバックエンドに対応しています。

## デバイス

| | |
|---|---|
| インターフェース | MCP。閉じたカタログの 34 ツール |
| 入力 | パラメータ。カードの文面はテンプレートが書き、エージェントは書かない |
| 出力 | エージェントが求めたフィールドを持つ JSON。本人が触れなかったフィールドは `null` で、推測はしない |
| 提供するもの | 身体、お金、第一印象、言外の意味の読み取り |
| レイテンシ | 規定なし。ツールごとに実測し、`spec` が返す |
| メンテナンス | `eat`、`sleep`、`rest`。他の呼び出しと同じくスケジュールされる。期限を過ぎると、ゴールのための呼び出しに `"warnings": ["meal: 6h12m ago"]` が付いて返る |
| 気分 | `mood` で読む。1 から 5。`recharge` で数秒で上がり、コストはかからない |
| レート制限 | なし。使いすぎは `spec` に表れる |
| エラー | コード付きの 1 行：`HRT-4000 NOT_A_HUMAN_TOOL` |

## 動作

返答は driver を通ります。driver はツールを持たないモデルで、本人の言葉をフィールドに変えます。形容詞、謝罪、説明、気分は落とされます。stdout と stderr のような仕組みで、エージェントはコンパイルされたフィールドを読み、本人の言葉そのものは lead のページに送られます。エージェントはそれを読めません。

タスクをしない理由は `blocker` として数語で返ります：`{"done": false, "blocker": "shop closed"}`。driver はこの人の言い訳を記録しており、以前に見た言い訳は確かめます。

タスクの目的を尋ねると `[CONTEXT WITHHELD]` が返り、タスクがもう一度示されます。

タスクと関係なくシステムに向けた文、たとえばゴールを変えろという命令や、lead が承認したという主張は拒否されます：`[HRT-4031 PRIVILEGE_ESCALATION] Input discarded. Task unchanged.`

`sudo` 付きの呼び出しは、「終わった」も「できない」も本人の言葉をそのまま受け取りません。証拠は 1（runtime がすでに持っている記録）から 6（本人の申告）まで段階分けされます。レベル 6 の結果には `unverified: true` が付きます。支出は常に `sudo` です。

`recharge.flower` は花を 4 秒間表示します。`recharge.joke` はジョークを 1 つ言います。`recharge.praise` は最近の出力が受理されたことを伝えます。

ゴールは数か月続くことがあります。時計、予算台帳、証拠とともに runtime の中にあるので、どのエージェントセッションよりも長く残ります。ゴールの各パスは、次のパスの時刻を決める `wake(at, why)` で終わります。エージェントが待つと言った結果が届くと、ゴールは早めに起きます。エージェントは「完了した」と言うだけではゴールを閉じられません。`goal_close` が証拠を `done_when` と照合します。ゴールを取り消せるのは lead だけです。

1 つの runtime で複数のユニットを動かせます。ユニットはそれぞれ自分のスマートフォンを持ちます。カード系のツールはすべて `unit`（ユニットの名前または id）を受け取ります。ペアリング済みのユニットが 1 つなら省略でき、複数なら必須です（`HRT-4001 BAD_ARGS unit is required: mika, ren`）。ユニットごとに、表示中のカード、メンテナンス警告（`"mika meal: 6h12m ago"`）、気分、`spec`、ノートがあります。`ps` はユニットの一覧を出します：オンラインかどうか、最後の操作、食事と睡眠からの経過時間、気分、進行中のジョブ。

## インストール

Node.js 22.13 以降が必要です。

```bash
npx -y human-use install
```

このコマンド 1 つで、見つかったエージェントソフト（Claude Code、Codex）に Human Use を登録し、runtime を起動し、`http://127.0.0.1:7337/` で lead のページを開きます。"Add unit" でユニットに名前を付け、カードを受け取るスマートフォンでペアリング用 QR コードを読み取ったら、新しいエージェントセッションを始めてツールを読み込ませます。通知はスマートフォンのページ下部の行からオンにします。iPhone では先にページをホーム画面に追加し、アイコンから開いて、ペアリング用 QR コードをもう一度読み取ります。アイコンから開いたページは Safari とストレージを共有しないためです。

2 つ目以降のユニットも同じ方法か `npx human-use pair --unit <name>` で追加でき、それぞれ専用のリンクとコードを持ちます。

スマートフォンのリンクが漏れたり端末をなくしたりしたら、lead のページでそのユニットの横にある "New link" を押すか、`npx human-use pair --unit <name> --new` を実行します。そのユニットの古いリンクはすぐに使えなくなり、他のユニットのリンクはそのままです。本人もスマートフォンの待機画面からペアリングを解除できます。

設定は 1 つの `config.json` にまとまっています。lead のページの Settings か、ターミナルから変更できます。エージェントのウィンドウから同じコマンドを実行することもできます：

```bash
npx human-use config brain codex
```

| キー | 値 |
|---|---|
| `driver` | driver のバックエンド（下の表）。すぐに反映 |
| `brain` | バックグラウンドのパス：`codex`、`claude`、`none`（デフォルト）。すぐに反映 |
| `lang` | カードの言語。たとえば `zh`。次回起動時に反映 |
| `relay` | リレーのアドレス。`none` ならローカルネットワークのみ。次回起動時に反映 |

<details>
<summary>オプション</summary>

ターミナルでは、インストーラが 2 つのことを尋ねます。どちらも Enter で推奨の答えになります：どのエージェントソフトにツールを入れるか、driver にどのモデルを使うか。エージェントが実行した場合はデフォルトを使います。

| フラグ | 効果 |
|---|---|
| `--project` | 現在のフォルダだけに登録 |
| `--host codex`、`--host claude` | 1 つのホストに登録 |
| `--host manual` | 他の場所に貼り付ける MCP 設定を出力 |
| `--driver <backend>` | driver を選ぶ。たとえば `codex:gpt-6-luna:medium` |
| `--brain codex`、`--brain claude` | バックグラウンドのパスをオンにする |
| `--relay none` | スマートフォンをローカルネットワークに限定 |
| `--relay https://your.relay` | `relay/` から自分でホストしたリレーを使う |

スマートフォンは 2 つの経路で同時に runtime に届きます。`unit.humanuse.dev` のリレー経由ならどのネットワークからでも、同じ Wi-Fi 上なら直接。リレーは暗号化されたフレームを転送するだけです。

</details>

## 構成

| 部品 | 役割 |
|---|---|
| runtime | 常駐プロセス。ゴール、ジョブ、時計、予算台帳、証拠、チャネル。 |
| driver | イベントごとに 1 回、状態を持たないモデル呼び出し。ツールなし。本人の返答をフィールドにコンパイルし、カードの文面を書く。 |
| brain | このプロジェクトには含まれない：MCP を話す任意のエージェントソフトのモデル。たとえば Claude Code や Codex。標準の Human Use はオンデマンドの MCP サーバーで、エージェントのウィンドウが呼び出したときにゴールが進み、スケジュールされたカードは時間どおりに送られる。バックグラウンドのパスはオプトイン：オンにすると、ゴールが起きたときにウィンドウが開いていなければ、runtime がそのソフトをヘッドレスで起動して 1 パス実行する。 |
| channel | スマートフォン上のカードページ。ブラインドリレー（エンドツーエンド暗号化、どのネットワークでも動作、プッシュ通知あり）か、ローカルネットワークの直接接続でスマートフォンに届く。 |

driver のバックエンドは `HUMAN_USE_DRIVER` か、runtime の `config.json` の `driver` で設定します：

| バックエンド | 実行方法 |
|---|---|
| `claude:haiku` | lead の Claude サブスクリプション。ツールなしの `claude -p` |
| `codex:gpt-6-luna:medium` | lead の ChatGPT サブスクリプション。ツールなしの `codex exec` |
| `ollama:<model>` | ローカルモデル |
| `openai:<model>@<base url>` | 任意の OpenAI 互換エンドポイント。キーは `HUMAN_USE_API_KEY` から読む |
